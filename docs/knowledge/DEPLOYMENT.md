# Публикация и хранение

## Разделение

- GitHub: `https://github.com/NieMandX/NURAY`, основная ветка `main`.
- GitHub Pages: `https://niemandx.github.io/NURAY/`.
- Публикуемая папка: `moscow-fidelity/web-preview/` через `.github/workflows/`.
- Object Storage: `https://nuray-scenes.s3.cloud.ru/`.
- Текущий открытый префикс: `assets-moscow-style-20261024-r14/`.
- Закрытые входы сборки: `backups/nuray-moscow-build-20261027.tar.gz` (см. `../build-snapshot-manifest.json`).

Публичное чтение ограничено указанным выпуском. Запись и перечисление всего бакета анонимно не разрешены. Новый релиз требует отдельного явно ограниченного правила чтения. Не включать публичный доступ ко всему бакету: будущие backups должны оставаться закрытыми.

CORS разрешает GET/HEAD из `https://niemandx.github.io` и `http://127.0.0.1:8776`; выдаёт Content-Length/Content-Range, max-age 3600. Для другого локального порта добавьте конкретный origin либо используйте 8776.

## Файлы

`../assets-manifest.json` — точные пути, длины и SHA-256 8430 runtime-файлов текущего выпуска, суммарно 4 572 345 209 байт (4,57 GB). Включены merged GLB, 49 групп BVH, каталог 400 тайлов, их меши, текстуры и surface effects.

Это 8430 логических файлов, но для работы требуется **202 облачных объекта**: 8229 мешей объединены байт в байт в `meshes.pack` размером 848 079 153 байта; остальные 201 файл хранятся отдельно. Индекс диапазонов входит в код viewer. SHA-256 контейнера и смещения логических файлов записаны в manifest. В бакете могут оставаться отдельные меши от первоначальной пробной загрузки; текущая публикация от них не зависит.

Файлы `*.bin.gz` уже сжаты и распаковываются viewer через DecompressionStream. **Не задавать им и `meshes.pack` HTTP Content-Encoding: gzip.** Иначе браузер разожмёт их до кода приложения и получится двойная распаковка. GLB: `model/gltf-binary`; JSON: `application/json`. Content-Length должен совпадать с manifest. Поддержка Range обязательна для контейнера тайлов и полезна для возобновляемого скачивания.

Build snapshot содержит текущую каноническую геометрию, семантическую модель, рельеф, объектные данные, входы преобразований и исходный московский capture/cache без исторических тяжёлых промежуточных попыток. Параметры ключей в source URL удалены. Runtime-файлы восстанавливаются отдельно по основному manifest. Архив приватный; для восстановления скачать через авторизованную консоль Cloud.ru и распаковать в корень клона.

## Проверка и выпуск

```sh
python3 scripts/verify_cloud.py
python3 scripts/restore_assets.py --mode merged --check-only
```

Первое проверяет наличие, размеры, CORS и gzip-заголовки 202 объектов, затем получает три диапазона контейнера (начало, середина, конец) и сверяет их SHA-256. Второе проверяет локальные SHA-256. `restore_assets.py` при скачивании тоже сверяет SHA-256, поддерживает продолжение частично загруженного файла. Для режима tiles/all скачивает контейнер один раз и восстанавливает исходные файлы, проверяя каждый. Контейнер остаётся рядом с ними: при локальном восстановлении нужно дополнительно около 848 МБ свободного места.

Сначала загрузить весь новый release, проверить его, затем переключать `config.json` и публиковать код. Не перезаписывать прошлый каталог несовместимой геометрией: GLB, BVH, textures и metadata должны соответствовать друг другу.

В Cloud.ru используется класс «Однозонный». При загрузке через консоль большие списки следует делить на партии: не отправлять 8000 абсолютных путей одним вызовом расширения браузера. Закрытие/перезагрузка вкладки может прервать текущую очередь.

Для больших файлов предусмотрен `scripts/upload_cloud.py` с возобновляемой multipart-загрузкой. Нужен `boto3` в отдельном Python-окружении. Временный сервисный аккаунт должен иметь только `s3e.viewer` и `s3e.editor` на нужный бакет, без общих ролей проекта и прав на ACL. Ключ отозвать после проверки передачи.

```sh
python3 scripts/upload_cloud.py /path/to/meshes.pack \
  --key assets-moscow-style-20261024-r14/meshes.pack \
  --credentials-file .local/cloud-credentials.json \
  --sha256 c85b1b60d4eb63eb574d4a3b2b98d6e8273fad743e355df728fd4bbaef9facb5
```

Файл учётных данных хранится вне Git с правами `0600`: поля `accessKeyId`, `secretAccessKey`, `tenantId`. Для Cloud.ru загрузчик добавляет tenant-префикс к ID ключа. Можно вместо файла использовать стандартное окружение или профиль SDK. Не вставлять секреты в команды, документацию или логи.

Загрузчик сверяет локальный SHA-256, отправляет части с Content-MD5, проверяет их ETag и сохраняет состояние в игнорируемой `.local/uploads/`. При повторном запуске проверяет уже переданные части и продолжает. После сборки объекта сверяет размер, SHA-256 metadata и фактические байты трёх диапазонов. Существующий несовпадающий объект не перезаписывает. Для резервного архива использовать ключ `backups/nuray-moscow-build-20261027.tar.gz`, сохраняя закрытый доступ.
