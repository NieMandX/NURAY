## Проверка и выпуск

```sh
python3 scripts/verify_cloud.py
python3 scripts/restore_assets.py --mode merged --check-only
```

Первое проверяет наличие, размеры, CORS и gzip-заголовки 202 объектов, затем получает три диапазона контейнера (начало, середина, конец) и сверяет их SHA-256. Второе проверяет локальные SHA-256. `restore_assets.py` при скачивании тоже сверяет SHA-256, поддерживает продолжение частично загруженного файла. Для режима tiles/all скачивает контейнер один раз и восстанавливает исходные файлы, проверяя каждый. Контейнер остаётся рядом с ними: при локальном восстановлении нужно дополнительно около 848 МБ свободного места.

Сначала загрузить весь новый release, проверить его, затем переключать `config.json` и публиковать код. Не перезаписывать прошлый каталог несовместимой геометрией: GLB, BVH, textures и metadata должны соответствовать друг другу.

В Cloud.ru используется класс «Однозонный». При загрузке через консоль большие списки следует делить на партии: не отправлять 8000 абсолютных путей одним вызовом расширения браузера. Закрытие/перезагрузка вкладки может прервать текущую очередь.

Для больших файлов предусмотрен `scripts/upload_cloud.py` с возобновляемой multipart-загрузкой. Нужен `boto3` в отдельном Python-окружении. Временный сервисный аккаунт должен иметь только `s3e.viewer` и `s3e.editor` на нужный бакет, без общих ролей проекта и прав на ACL. Ключ отозвать после проверки передачи.

```sh
python3 scripts/upload_cloud.py /path/to/meshes.pack \
  --key assets-moscow-style-20261024-r14/meshes.pack \
  --credentials-file .local/cloud-credentials.json \
  --part-mib 5 --addressing-style virtual \
  --sha256 c85b1b60d4eb63eb574d4a3b2b98d6e8273fad743e355df728fd4bbaef9facb5
```

Файл учётных данных хранится вне Git с правами `0600`: поля `accessKeyId`, `secretAccessKey`, `tenantId`. Для Cloud.ru загрузчик добавляет tenant-префикс к ID ключа. Можно вместо файла использовать стандартное окружение или профиль SDK. Не вставлять секреты в команды, документацию или логи.

Загрузчик сверяет локальный SHA-256, отправляет части с Content-MD5, проверяет их ETag и сохраняет состояние в игнорируемой `.local/uploads/`. При повторном запуске проверяет уже переданные части и продолжает. После сборки объекта сверяет размер, SHA-256 metadata и фактические байты трёх диапазонов. Существующий несовпадающий объект не перезаписывает. Для резервного архива использовать ключ `backups/nuray-moscow-build-20261027.tar.gz`, сохраняя закрытый доступ.

На нестабильном соединении части по 5 МиБ уменьшают длительность отдельного запроса. Размер части уже начатой передачи менять нельзя: состояние привязано к размеру и контрольной сумме файла. Ошибка Cloud.ru HTTP 499 повторяется загрузчиком ограниченное число раз; после исчерпания попыток повторный запуск продолжит проверенную передачу.
